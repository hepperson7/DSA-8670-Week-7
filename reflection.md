This was an interesting experience, using Codex to generate analysis. I was trying to be specific in my prompting, but still had room to improve. For example, I gave Codex column names from the dataset, but I mistyped / misnamed them. For example, I told it to evaluate square footage, which is not an actual column name. I was surprised that it did pick the column Gr Liv Area because those are quite different in name. 
I was also surprised to learn I did not have Python installed on my machine, and that Codex installed it and the necessary packages for its work (with my permission). Codex was also pretty insightful when it came to explaining the results, which is usually a struggle of AI. It stated that the regression model had # of bedrooms negatively impacting selling price, but warned against making the claim that adding bedrooms alone decreases value. It referenced other factors that coincide with number of bedrooms, such as the house's square footage, age, and condition. 

If I were to do this again, I'd be more careful in my prompting. It's easy for me to use human language such as "evaluate selling price" and expect that Codex picks the right field. In this case, it asked me if I meant SalePrice, which I did. However, in more complicated situations, it will be important to be super specific in what I ask Codex. Having a well-written prompt will also save time by minimizing the number of clarification and rework prompts needed. 

Also, with AI there is a temptation to accept output without reviewing it as thoroughly as we should. I tend to do that, especially when AI generates large blocks of code. However, this is not good practice and I need to review the code line by line, as if I wrote it. In this assignment my review could have been more thorough, it was basically a gut check that the code made sense. It will be extremely necessary to have good code review practices with the capstone project.
